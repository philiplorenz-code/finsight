# Frontend API integration

The frontend follows `../../docs/api-contract.md`. All requests use same-origin `/api`, `credentials: same-origin`, no-store fetching and cookie sessions. Vite proxies `/api` to `localhost:8000`; production nginx proxies unchanged paths to `api:8000`. Never configure browser-side provider keys or external banking endpoints.

## Implemented routes

| View | Requests and interpretation |
|---|---|
| Authentication | GET `/auth/status` → `{initialized,authenticated}`. If authenticated, GET `/auth/me` obtains the in-memory `csrf_token`. POST `/auth/setup` sends `{email,password,bootstrap_secret}`; POST `/auth/login` sends `{email,password}`. POST `/auth/logout`. No passwords, tokens or financial query caches are persisted in browser storage. |
| Overview | GET `/overview?start&end`. `currencies` contains separate server-calculated totals; the selected currency filters totals, categories and trends, never sums currencies. Maps `observed_balance`, `monthly_obligations`; savings_rate is a ratio and formatted as a percentage. Named periods: current month, previous complete month, 3/6/12 calendar months including the incomplete current month, current year, custom range. Historical as-of sends month-start through the selected date; the API selects balances observed on/before that date. Historical metadata/allocation limitations are visibly disclosed. No overview figures are invented for missing values. |
| Accounts | GET `/accounts`; PATCH `/accounts/{id}` sends editable fields only. GET `/accounts/{id}/balances` reads `{observed_date,amount}` observations. Purpose and ownership follow server enums. |
| Transactions | GET `/transactions?page&page_size=25` with `search,start,end,account_id,category,min_amount,max_amount,merchant,is_transfer,contract,tag,currency,view`. Canonical MCP explorer links hydrate visible `start`/`end` date fields; legacy `date_from/date_to`, `amount_min/amount_max` and `contract_id` aliases remain supported. Canonical parameters win collisions regardless of query order, and editing/clearing removes the equivalent alias to prevent stale filters. Active advanced filters expand on entry. View (`all_transactions`, `included_spending`, `owned_liquid`) and currency controls remain visible even when other filters are collapsed. Missing view displays all transactions, preserving the API's existing default; explicit selections use the backend's canonical view predicate shared with MCP. GET `/transactions/{id}` includes sensitive source values, shown only locally as escaped text. PATCH `/transactions/{id}` uses `category_override` and string-array `tags`; POST `/transactions/{id}/reset`. Transfer flags are shown but not editable because this API does not support transfer overrides. |
| Imports | POST `/imports/preview` then POST `/imports`, both multipart `file`; GET `/imports` for persistent history. Preview renders row count, column names and server warnings, not invented sample records. No `full_snapshot` assumption. Upload response is synchronous; spinner indicates pending work, not a fake percentage. Failed import retry means selecting and uploading the file again; no unsupported retry route is called. Client cap 25 MiB; server limits and XLSX validation remain authoritative. |
| Buckets | GET/POST `/buckets`, target is decimal string. PUT `/buckets/{id}/allocations` replaces the full allocations array; existing account allocations are preserved in form state. POST `/buckets/{id}/obligations` sends decimal strings, `period`, optional due date and scheduled contribution amount. Server enforces disjointness and ownership. |
| Contracts | GET `/contracts` → `{items,warnings}`; maps `period`, `annual_cost`, string transaction-ID evidence into explorer links. No contract edit route assumed. |
| AI | GET `/ai/usage` → `{currency,runs}`. New AI costs are EUR, independent of the financial-data currency. Each historical run uses its own currency, never an envelope-level fallback: USD stays USD with a legacy badge, missing/null/unknown currency shows exact raw amounts and an explicit reconciliation warning. Non-EUR/unknown policies or price currencies are not relabeled or overwritten by the settings form. POST `/ai/chat` sends only `{topic,start,end,currency}`: bounded topics `cashflow,categories,coverage`, deliberately no free-form prompt or banking identifiers. Answer rendered as plain text, query evidence resolves to filtered transactions. GET `/findings`; PATCH `/findings/{id}` changes acknowledged/dismissed status. |
| Settings | GET/PATCH `/settings`. Complete nested `ai` policy and `notifications` preferences match the implemented integration contract, including verified EUR-per-million model prices, lifetime/monthly/channel/run limits, runtime limits and separate proactive consent. Quiet hours are converted to minutes after midnight. Provider/ntfy authentication secrets are configured on the server only. POST `/notifications/test` reports its returned state, not confirmed delivery. GET `/notifications` shows delivery/suppression history. |
| MCP consent | `/mcp/authorize?request_id=<uuid>` remains inside `AuthGate` and `Layout`; login/setup preserves the URL. GET `/mcp/authorization-requests/{id}` reads `{id,client_id,client_name,scopes,expires_at,resource,...}` (flat client fields, matching `apps/api/app/mcp_auth.py`). POST `/mcp/authorization-requests/{id}/decision` sends `{decision:"allow"|"deny",scopes:string[]}`, **not** `{approved}`. Denial sends an empty scopes array; approval includes only requested scopes, with `finance:transactions` separately opted in and off by default. Existing cookie-session CSRF applies. `{redirect_url}` is followed only after strict absolute HTTPS/HTTP-loopback URL validation; user-supplied redirect parameters are never read. |
| MCP settings | `/settings` links to independent `/settings/mcp`; no AI/notification form validity or `/settings` response is needed. GET `/mcp/connections` supports the integration envelope `{enabled,endpoint,scopes,connections:[{id,client_name,scopes,created_at,last_used_at?,revoked?,...}]}`. Compatibility with the initial backend's bare grant array displays unknown operator status/no endpoint rather than guessing. Revoked grants are omitted. DELETE `/mcp/connections/{id}` uses existing CSRF and refetches connections. No UI enablement override, provider credentials, OAuth bearer tokens or persistent query cache. |

### External MCP disclosure / deployment handoff

Both MCP pages disclose external client/provider access to queried financial data, separate client LLM billing outside FinSight's AI budget, read-only tools, no IBAN/raw references by default, and the detailed transaction scope. Consent requires an unchecked explicit transmission checkbox and an explicit allow button; denial requires no checkbox. Unknown scopes, expired requests and malformed request IDs cannot be approved. Backend validation remains authoritative. Connection revocation does not erase data already retained by external providers.

R1 consent-phishing review fix: authorization responses include `redirect_uri:string`. Consent displays the registered callback URI, its parsed origin and the `resource` as escaped, inert text, with long-URL wrapping; none is linked or fetched. DE/EN warnings explain that the client name is self-asserted, not verified by FinSight, and that even “ChatGPT” is not identity proof. The unchecked transmission checkbox also confirms that the owner independently checked the registered callback origin against the intended provider. Missing/unsafe callback URIs block approval, never denial. The backend remains responsible for exact registered redirect validation. Synthetic browser regressions use the spoofed name “ChatGPT” with an `attacker.example.invalid` callback, verify visible URI/origin/resource and no metadata requests/links, and check long-URL overflow at 390px in both languages on desktop/mobile projects.

R1 verification: **37 Vitest tests passed; 67 Playwright tests passed, 1 intentional skip; production build passed.** No changes to nginx or proxy tests were made for R1.

Transaction-link integration follow-up: **37 Vitest tests passed; 75 Playwright tests passed, 1 intentional skip; production build passed.** Eight new desktop/mobile browser cases cover canonical MCP link hydration, legacy aliases, canonical-over-alias precedence, alias removal on edit/clear, pagination reset, all three view selections, visible currency changes and mobile overflow. This follow-up changes only `src/pages/transactions.tsx`, its new browser tests and this API note; nginx/proxy configuration is untouched.

`MCP_ENABLED=false` remains the server-side default. The UI cannot enable it. ChatGPT instructions describe Settings → Apps → Developer mode → remote MCP with OAuth, publicly reachable HTTPS and provider/plan/workspace/version availability caveats; this is **not** a claim of live ChatGPT verification. The endpoint is displayed/copied only when supplied as a valid absolute URL by the API, never fabricated from the SPA origin.

Proxy integration is owned outside this frontend change: `/mcp/authorize` must reach SPA fallback, whereas exact `/mcp` is the remote MCP API resource; `/oauth/*` and OAuth discovery paths must reach the API without access-log leakage. Do not broadly proxy `/mcp/` to the backend and swallow the SPA consent route. `apps/web/nginx.conf` is deliberately unchanged by this work.

### Explicit AI provisioning and effective limits

The settings page offers authenticated `POST /ai/consent` with `{enabled:true,external_consent:true,proactive_consent:false}` only after the owner explicitly checks enablement and external consent. It provisions/refetches the operator's reviewed configuration without a provider request. The revoke button posts all three flags false, including for legacy policies. Refreshing consent must not clear run liabilities/history; the UI never requests ledger deletion or currency conversion.

Persisted settings alone cannot enable outbound calls. Both `AI_ENABLED=true` and `AI_EXTERNAL_CONSENT=true`, valid `AI_PROVIDER_BASE_URL` / `AI_API_KEY`, exact `AI_MODEL` / `AI_MODEL_ALLOWLIST`, and verified conservative `AI_INPUT_EUR_PER_MILLION` / `AI_OUTPUT_EUR_PER_MILLION` are operator responsibilities. Proactive reports additionally need `AI_PROACTIVE_ENABLED=true` and separate owner consent. Effective runtime/budget caps are the minimum of environment ceilings and persisted policy; the displayed policy limits are not a promise of spendable budget. Scheduled channels share the environment scheduled cap. `AI_RETRY_LIMIT` must be zero. See `../../docs/ai-agent.md` for exact variables, `/ai/settings`, legacy reconciliation and transmission boundaries. No provider credential is accepted or persisted by this frontend.

## Public origin / HTTPS proxy topology

- The shipped nginx forwards `Host $http_host`, preserving the browser's public authority, including `:8080` or another non-default port. A direct local deployment at `http://localhost:8080` therefore reaches the API with that Host and accepts its matching browser Origin. Do not replace it with `$host`, disable origin checks, or use an origin-less smoke client as evidence of browser correctness.
- For public TLS, choose one canonical origin, for example `https://finance.example.org` (or explicitly `https://finance.example.org:8443`). Configure the **API environment** with `FINSIGHT_ALLOWED_ORIGINS='["https://finance.example.org"]'`, matching exact scheme/host/port, and keep `FINSIGHT_COOKIE_SECURE=true`. `APP_URL` alone is not an origin configuration. Allow only your own intended public origins, never `*` or arbitrary requesting origins.
- A TLS ingress must validate/restrict the public Host to that canonical authority, preserve its port when forwarding to web:8080, overwrite untrusted client forwarding headers, and keep API:8000 inaccessible publicly. The inner nginx sets `X-Forwarded-Proto $scheme` from its own connection rather than trusting a client-provided scheme. When ingress → web is HTTP, the explicit HTTPS allowed-origin entry avoids relying on untrusted scheme inference. Do not globally trust arbitrary forwarded headers; any deployment-specific proxy trust must be restricted to the ingress network.
- `FINSIGHT_COOKIE_SECURE=false` is only for explicit local HTTP development/testing. A deployed browser regression must exercise setup/login through the shipped proxy with the actual `Origin: http://localhost:8080` (and any chosen custom port), then reject an attacker Origin. HTTPS must separately be exercised through its real canonical ingress.
- **All nginx access logs are disabled at server level**, including SPA navigation, `/assets`, `/healthz` and `/api`: frontend routes/query strings can contain private account/category/search filters. Do not re-enable request-URL logging at another proxy without an explicit privacy review.

## Security and presentation boundaries

- Mutations carry `X-CSRF-Token`, obtained from `/auth/me`, login/setup JSON or a readable `csrf_token`/`csrf`/`finsight_csrf` cookie. Multipart requests do not override browser-generated content-type boundaries. Login/setup are server-exempt from CSRF; no client-side authentication bypass exists.
- API errors are mapped to generic localized messages; raw server exception strings are never rendered. 401 on protected queries/mutations refreshes session state. A CSRF failure does not automatically replay a mutation.
- API authorization, upload parsing, financial correctness, budget accounting and notification delivery are backend responsibilities. Browser checks are usability constraints, not security gates.
- Monetary values remain decimal strings in mutation bodies and tables. Currency formatting passes the exact decimal string to modern ECMA-402 `Intl.NumberFormat`; a capability probe falls back to the untouched decimal lexeme plus currency on older engines, never to `Number`. Large cents such as `123456789012345.67` are preserved. `Number` is used only for chart rendering, visual progress, rate display and positive-limit validation; never to calculate stored balances, contributions, expenses or cross-currency totals.
- Named periods use Europe/Berlin calendar dates. Custom periods require start ≤ end. No historical allocation snapshot or forecast is fabricated.
- Only `finsight-language` and `finsight-theme` are in localStorage. There is no analytics, external font, persistent query cache or third-party frontend request.

## Known limitations / integration verification still required

- Browser tests use synthetic route mocks, not a live deployed API. Real cookies behind TLS, migration/Compose operation, real XLSX parser behavior, provider billing and ntfy delivery are not verified by these frontend tests.
- Native accessible components are shadcn-style, not generated Radix/shadcn components. Charts are Recharts; cashflow also has a text table. Mobile navigation traps keyboard focus, closes with Escape, and restores focus.
- Browser preferences currently remain local; timezone defaults to Europe/Berlin and main currency defaults to EUR. ntfy timezone preferences are persisted to the server. Some technical enum/model configuration labels remain English in the German interface.
- Bucket creation/funding/obligations are implemented; bucket renaming/deletion, scheduled contribution editing, allocation history and account-link-only editing are not exposed. Transaction revisions are retained by the backend but no revision-diff UI is provided.
- AI uses the backend's bounded topic interface, not unrestricted chat. Proactive opt-in and limits can be configured, but runtime scheduling/provider operation must be verified separately.
- Import preview shows schema/counts/warnings; the API intentionally does not return private sample rows. Uploads are synchronous and cannot survive closing the browser before completion; no background-upload claim is made.
- Dockerfile expects `apps/web` as its build context. Container runs as UID 101 on port 8080. Deployment TLS/HTTPS is an upstream operator responsibility; API secure cookies need HTTPS (or explicitly insecure local-development configuration).
